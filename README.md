# Personalized Movie Recommendation System Using Collaborative Filtering
HCLTech Career Shaper Programme 2025-26 | Project No. 28 | Individual project

User-based and item-based collaborative filtering and SVD matrix factorisation, evaluated with RMSE and precision@K, audited for diversity and fairness, served through a Flask REST API and a Streamlit dashboard.

> **All ratings beyond the 473 rows of the provided file are synthetic** (generated by `src/generate_data.py`, seed 42). Results describe this synthetic dataset, not real viewers.

## Problem
Viewers struggle to find films they will enjoy in a large catalogue, and popularity lists bury regional-language films and create filter bubbles. See `docs/project_charter.md`.

## Data
`data/raw/dataset.csv` (provided, 500 rows, 8 movies) was too sparse and inconsistent for collaborative filtering, so it was extended to 5000 ratings by 309 users on 126 films (`docs/data_source.md`). Cleaned file: `data/processed/dataset.csv`; dictionary: `data/processed/data_dictionary.csv`.

## Approach
Cleaning -> EDA (`notebooks/03_eda.ipynb`) -> per-user chronological split (locked test set) -> baselines -> user-based CF / item-based CF / SVD tuned on two rolling folds -> CF + popularity blend -> MMR diversity re-ranker -> one final test evaluation -> API and dashboard.

## Results (test set, opened once; details in `docs/evaluation_report.md`)
| Question | Result |
|---|---|
| Item CF RMSE vs item-mean baseline | 0.7224 vs 0.7576 (difference -0.0352 (95% CI -0.0562 to -0.0154)) |
| Item CF vs user + movie bias baseline | 0.7224 vs 0.7234 (no significant gain: -0.0009 (95% CI -0.0043 to +0.0025)) |
| P@10, deployed blend vs popularity | 0.0796 vs 0.0792 (tie: +0.0004 (95% CI -0.0039 to +0.0046)) |
| Catalogue coverage@10 | 15.9% deployed; 31.0% with the safe diversity re-ranker (P@10 0.0775) |
| API latency (median, 300 requests) | 3.0 ms |

Honest reading: collaborative filtering beats item averages but adds almost nothing beyond user and movie biases on this sparse data; the popularity blend only ties popularity; the re-ranker doubles coverage for a small accuracy cost.

## How to run
    bash setup.sh                        # creates venv, installs requirements (Windows: python -m venv venv, activate it, pip install -r requirements.txt)
    python api/app.py                    # REST API on http://127.0.0.1:5000  (docs/api.md)
    streamlit run app/dashboard.py       # dashboard on http://localhost:8501
    python -m pytest -q tests            # 56 tests

Rebuild from the raw file: `python src/generate_data.py`, `python src/clean.py`, `python -m src.make_split`, `python -m src.tune`, `python -m src.diagnostics`, `python -m src.finalize_stage9`, `python -m src.stage10 --split val`. The final test evaluation (`python -m src.stage10 --split test`) refuses to run twice.

## Ethics
Pseudonymous user IDs, no names or demographics, synthetic ratings, no real personal data. Filter-bubble risk is measured (coverage, list diversity, exposure Gini, tail share) and mitigated with a diversity re-ranker. Demographic fairness cannot be assessed because the data has no demographic attributes; fairness is checked across activity, generosity and taste groups. MovieLens is cited as inspiration; none of its data is included. AI assistance is disclosed in `docs/ai_usage_disclosure.md`.

## Limitations
Synthetic data; sparse ratings (about 16 per user); popularity confound in the ranking test; about 13.4% of test ratings are noisy original rows; small test set; per-user split is not a strict global-time replay; blend weight and re-ranker settings were chosen on validation data (the validation-to-test drop shows the optimism).
